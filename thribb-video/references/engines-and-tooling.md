# Visual engines: implementation reference

Snapshot: 2026-10-17. Re-read installed-version documentation before changing a project. Source snapshots and tests are in [tooling/sources.md](tooling/sources.md), [tooling/verification.json](tooling/verification.json) and [tooling/upstream-skills.md](tooling/upstream-skills.md).

## 1. Choose by the reasoning operation

| Need | First candidate | Why | Do not assume |
|---|---|---|---|
| Exact mathematical transformations, graphs, equations, parameter-driven geometry | Manim CE or ManimGX | Objects can retain identity while a mathematical state changes | Same names mean identical behavior across engines |
| Reproduce or study code written for Grant's own engine | ManimGL | This is the 3b1b/manim branch, using manimlib | CE examples will run unchanged |
| Interactive mechanical metaphor or isometric article figure | Anatomy | SVG geometry, shared model, controls, physical parts, optional WebGL | Decorative hardware improves an abstract argument |
| Assemble HTML/SVG/math clips, captions, narration, and other rendered media | HyperFrames | Seekable browser composition with framework-owned media timing | A normal interactive webpage is a deterministic video |
| Rust-native frame computation, SVG scenes, Skia or CPU rasterization | fframes | Video/Scene traits return SVG trees for explicit frames | It is a JavaScript or browser-only framework |
| Illustrated article with broad browser support | SVG/PNG stills generated by an appropriate engine, with optional interactive enhancement | The explanation survives without autoplay or a GPU | MP4 playback or WebGPU is an acceptable sole explanation |

Choose the simplest engine that can express the essential change. A request naming all these engines means the skill should know how to select and combine them, not that every artifact needs five renderers. Keep the mathematical model independent from rendering where practical.

## 2. Manim is a family, not one package

### Manim Community Edition

Source: https://github.com/ManimCommunity/manim

- Python distribution and import: `manim`.
- Snapshot manifest: version 0.22.0, Python >=3.11.
- Scene API: subclass `Scene`, implement `construct`, add mobjects, advance time with `play` and `wait`.
- Common types: `Text`, `MathTex`, `VGroup`, `Axes`, `ValueTracker`; common operations: `Create`, `Write`, `Transform`, `.animate`.
- Standard CLI pattern: `manim -ql scene.py SceneName`; `-s` saves the final frame. Validate the installed CLI before using unfamiliar flags.
- Dependencies include Cairo/Pango, Python bindings, PyAV, numerical packages; LaTeX/toolchain requirements depend on the text path used. A Python wheel is not proof the native libraries are ready.
- Tested here: attempted isolated install of 0.22.0, blocked building ManimPango because `pangocairo >=1.30.0` development metadata was absent. No CE render was performed.
- Do not silently switch to GX and report a CE example as tested.

Reproducible project setup recipe, not executed successfully here:

```sh
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python 'manim==0.22.0'
.venv/bin/manim -ql scene.py AreaExample
```

Install the documented OS packages only in an environment you control. Do not escalate privileges merely to make the recipe pass.

### Grant's ManimGL

Source: https://github.com/3b1b/manim

- Distribution: `manimgl`, import: `from manimlib import *`.
- Snapshot README: Python >=3.10; FFmpeg and graphics support; optional LaTeX for TeX; Pango development headers on Linux.
- CLI: `manimgl scene.py SceneName`; `-w` writes video, `-s` skips to the end and saves the final frame. `manim-render` is also documented upstream.
- Common historical/API distinction: `ShowCreation` and `Tex`/`TexText` are not a safe drop-in substitution for CE's `Create` and `MathTex`.
- Installation and renderer configuration must follow this branch's docs. The repository itself warns not to mix CE installation instructions with ManimGL.
- Not installed/rendered in this verification. The same missing Pango development support affects feasibility, and graphics capability must be tested separately.

This distinction matters when studying source code associated with 3Blue1Brown. Knowing CE or GX does not establish exact compatibility with Grant's scene files.

## 3. ManimGX

Sources: https://github.com/academa-labs/manimgx and https://manimgx.academa.ai

### Native workflow

- Distribution/import: `manimgx`, normally `import manimgx as m`.
- Snapshot and installed release tested: 0.1.1; Python >=3.13. Tests used isolated Python 3.14.7.
- Rust + wgpu rendering. Linux wheels include a software Vulkan/lavapipe route; hardware availability still affects performance.
- Bundled text/math and video encoding avoid a separate LaTeX installation for its supported TeX-to-Typst path.
- CE-like authoring API, not identical semantics and not ManimGL compatibility.

```sh
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python 'manimgx==0.1.1'
.venv/bin/manimgx inspect scene.py SceneName
.venv/bin/manimgx render scene.py SceneName -r 1280x720 --fps 30 -o draft.mp4
```

The upstream standalone alternative is `uv tool install --python 3.14 manimgx`. Prefer a project environment and recorded lock for shared reproducibility.

Important differences from CE, documented upstream:

- Do not import CE submodules under a `manimgx.*` path. Public names are exported from the package.
- GX uses `-r WIDTHxHEIGHT` and `--fps`, not CE's `-ql`/`-qh` shorthand.
- `MathTex` converts supported LaTeX through Typst. Arbitrary LaTeX packages and `\def` do not convert.
- Portrait frames use the short side as 8 scene units by default; CE's portrait framing differs.
- Updaters and simultaneous transformations have defined GX semantics. Test simulations at more than one FPS rather than assuming matching frame stepping.
- Keyword misspellings may be ignored at runtime. Static typing is useful in addition to rendering.
- `inspect` checks sampled 2D layouts. Its 3D storyboards do not establish absence of 3D occlusion or clipping.

### Audio is an explicit decision

`Sound(file)` can be scheduled in `play`; `add_sound` can overlay a recording without waiting. `say(text, animations...)` aligns animations to bracketed words, but the documented default voice uses ElevenLabs through fal.ai and needs `FAL_KEY`. Do not call it as an unannounced free/local operation. No synthesis or audio mixing was tested here. Use authorized recordings or explicitly selected services, and check the resulting audio separately.

### Browser article enhancement

The npm package registers `<manimgx-player>`. A bundler can import `manimgx`; Python can live in a nested `<script type="text/python">`, or JavaScript can set `player.source`. Documented controls include `play()`, `pause()`, `currentTime`, and `duration`.

The browser path uses Pyodide in a worker and WebGPU, with float32 blending and depth-format requirements. It is not a universal-browser fallback. Provide a meaningful still image, caption, and written argument when WebGPU, download bandwidth, or JavaScript is unavailable. Browser rendering was not tested here.

### Observed export limitation

The 0.1.1 CLI reported requested FPS, but the actual files did not have `duration * FPS` frames during static holds. The 8-second test requested 24 FPS but had 145 encoded frames, average rate 3480/193, and a format duration about8.04s. The last decoded frame was correct; seeking into its long static tail with FFmpeg did not return a frame. Do not present this as constant-FPS export.

For a silent, already-correct scene whose intended duration is known, the tested normalization was:

```sh
ffmpeg -i gx-shear.mp4 -vf 'tpad=stop_mode=clone:stop_duration=3,fps=24' \
  -t 8 -an -c:v libx264 -crf 18 -pix_fmt yuv420p gx-shear-cfr.mp4
```

That derivative was 8.000s, 192 frames,24/1 FPS. The padding is specific to this silent test. Never extend an arbitrary clip or discard real audio with `-an` as a generic repair. Verify duration, intended holds, final frame and audio sync for each project. Keep raw source output and label normalization.

## 4. Anatomy

Source: https://github.com/wheresryan22/anatomy

Anatomy is a reusable skill, geometry kit and examples, not an anatomy-model generator or one pip package.

- Node >=20.10 and Chrome/Chromium for the documented checks.
- Framework-free path: Node ESM builds standalone HTML/SVG.
- React/Next path: geometry and static art on the server; client hooks move refs and update readouts.
- Optional WebGL and beta 3D. Neither was tested here.
- Kit exports include `fitProjection`, `slabOf`, `cylinder`, `extrude`, `solidSvg`, `lineSvg`, `figureSvg`, `plateHtml`, and `pageHtml`.
- World coordinates are `[x,y,z]`, z up; projection and painter's order are explicit.
- `kit/iso-kit.mjs` is the plain ESM core; `kit/iso-kit.ts` is the typed version. `kit/react/draw.tsx` and `live.tsx` own the React split.

Upstream example smoke route, actually executed:

```sh
node examples/dial-indicator/build.mjs
node examples/dial-indicator/build.mjs --light
node scripts/capture.mjs examples/dial-indicator/dial-indicator.html \
  --width 390 --out phone.png
```

The existing dial-indicator example built and its phone screenshot had no sideways scroll and a clean console. Both themes were visually inspected. Fine mechanical details were faint at phone size, so this is a runtime smoke test, not evidence of teaching-ready contrast.

For new work:

1. Choose a concrete mechanism whose behavior maps to the concept. State what moves and what it means. If no honest mapping exists, use mathematical geometry instead of a fake machine.
2. Separate a pure model from drawing. Use the same state to drive motion, readout and caption.
3. Read the upstream `SKILL.md`, nearest complete example and `references/craft.md` before designing. The skill's detailed-object quality bar includes purposeful parts, not arbitrary density.
4. Use `fitProjection` over all extreme points; check at390px. A correct isometric drawing can still be unreadable.
5. Depth-sort solids, split wrapping shapes into back/front, and avoid impossible intersections.
6. Read `references/kit.md`, `motion.md`, `verify.md`; read `react.md`, `webgl.md` or `3d.md` before their respective paths.
7. Use capture/drive scripts for keyboard, pointer, reduced-motion and no-WebGL fallback checks. For pipes/round parts use the geometry audit, not only screenshots. `lines.mjs` checks floating line ends separately.
8. For static article export, `figureSvg({standalone: "dark" | "light"})` embeds styles. Ensure static SVG still communicates the point with motion absent.

Do not publish to the optional Anatomy community gallery just because a figure is finished. That is a separate disclosure/destination choice.

## 5. HyperFrames

Sources: https://github.com/heygen-com/hyperframes and https://hyperframes.heygen.com

- npm CLI package: `hyperframes`; installed/tested0.8.168; Node>=22 and FFmpeg.
- HTML/SVG composition rendered through Chrome; seekable animation runtimes. GSAP is the documented common path; other adapters exist.
- Native composition, not React required. It can combine externally rendered Manim/GX MP4s with authored HTML/SVG, audio and captions.

Local-only installation used here:

```sh
npm install --save-exact hyperframes@0.8.168 gsap@3.14.2
export HYPERFRAMES_NO_TELEMETRY=1 DO_NOT_TRACK=1
# Only if choosing an existing browser:
export HYPERFRAMES_BROWSER_PATH=/path/to/chrome
npx hyperframes check ./project --strict --json
npx hyperframes render ./project --workers 1 --low-memory-mode \
  --fps 15 --quality draft --output out.mp4
```

Project installation can run scripts in packages. Inspect package/source policy for the environment being used. The smoke installation used `--ignore-scripts` and an already-installed Chrome; no sign-in, cloud command, hosted assets or public feedback was used.

### Composition contract

- Standalone `index.html` root is directly in body, not wrapped in `<template>`.
- Root: `data-composition-id`, `data-width`, `data-height`, and explicit or inferred duration. Size the root with100%, not a second contradictory pixel canvas.
- Sub-composition: `<template>` wraps its root, including its style/scripts. Match the host id, child composition id, and timeline registration key to avoid silent wiring errors.
- Register a completed paused timeline at `window.__timelines[compositionId]`.
- Root `data-duration` governs output length, not just GSAP's last tween.
- Timing uses `data-start` and `data-duration`. `data-track-index` is an editing lane, not a z-order or timing guarantee.
- Framework owns timed clip/media visibility and playback. Do not use `video.play()` or arbitrary realtime clocks to drive capture.
- Put animation inside a timed clip wrapper rather than tweening its lifecycle visibility.
- Avoid unseeded randomness, live fetches, Date.now, performance.now and asynchronous state that changes at capture time. Precompute state and load required assets before capture.
- Give media and editable timeline nodes stable unique ids. Local assets avoid network/CDN changes during export.
- Do not nest a timed `<video data-start>` under another ordinary timed node: this is a documented media-timing bug. Either the wrapper or video owns timing, not both.
- Do not set `crossorigin` on video/audio under the current documented contract; the linter rejects it.

The tested geometry-only example uses an SVG as the timed top-level node. This avoids a nested-structure Studio warning without changing the explanation.

### Gates and caveats

Use `check`, not deprecated `validate`/`inspect`/`layout` in new recipes. Confirm `browserSkipped:false`. Zero errors with zero samples is not a completed browser check. A `*.motion.json` sidecar can assert visibility order and in-frame behavior. Automated geometry/contrast checks do not inspect a canvas's meaning or prove correctness.

`snapshot --at 1,2,3 --describe false` captures explicit moments; `--describe false` prevents optional external Gemini analysis if credentials happen to exist. Inspect decoded final frames too. A preview page is not the encoded output.

Local quality presets: `draft`, `looks`, `delivery`. One worker/low-memory mode is safer on constrained machines. Our test used software llvmpipe screenshot capture, not the faster BeginFrame/GPU path. Do not quote upstream speed claims as a benchmark result.

Optional hosted render, Lambda/Cloud Run, publish, auth, media generation, usage/account introspection and feedback are distinct operations. They can involve credentials, disclosure, metering or public destinations; they are not prerequisites to a local geometry render. Do not run them just because an upstream skill suggests them. Anonymous telemetry can be disabled as above.

## 6. fframes / fframes.studio

Sources: https://github.com/dmtrKovalenko/fframes and https://fframes.studio

- Rust library and cargo generator, not a TypeScript animation package.
- Snapshot library/generator manifests:1.2.0, Rust2024 edition. Check the installed toolchain's compatibility rather than pinning a guessed minimum Rust release.
- Native pipeline returns SVG trees from `Video::render_frame` and `Scene::render_frame`, using `fframes::svgr!` and Rust expressions.
- `Video` defines FPS, WIDTH, HEIGHT, duration and audio; optional scenes compose a timeline.
- `frame.seconds()` is scene-relative; global frame index is separate. Use the correct clock for cross-scene labels/events.
- `timeline!` and easing/springs animate values. Keep time calculations shared with audio, labels and geometry.
- Skia GPU default uses Metal/Vulkan; CPU backend lacks the native preview window and is slower per upstream docs.
- Native FFmpeg is linked, not simply the system `ffmpeg` executable called as a subprocess. A present FFmpeg CLI is not enough to compile it.

Documented setup recipe, not run here:

```sh
cargo install --locked cargo-fframes
cargo fframes new area-proof --format landscape --fps 30 --backend cpu --yes
cd area-proof
cargo build --release
cargo run --release -- timeline
cargo run --release -- inspect
cargo run --release -- strip -n 12
cargo run --release -- render -o out.mp4
```

Pin the actual resolved generator/library and lockfile after installation. Do not assume a current main-branch API is in an older registry release.

The README documents system encoder/development packages, platform-specific FFmpeg archives, and Skia first-build downloads. Rust/Cargo are absent in the verification environment, so no compile or render was attempted. This is an explicit untested integration path, not a recommendation that it will build unchanged.

CLI review capabilities documented in the inspected snapshot:

- `timeline`: scene and audio ranges.
- `inspect`: SVG, text, assets and runtime checks; `--pops` performs denser change checks.
- `strip`, `frame`, `onion`: contact sheets, full-size/cropped frames, trajectories.
- `audio analyze`, `audio at`, `audio render`: numeric/mix inspection.
- GPU `preview`: native realtime review.
- `render`: export. Verify actual stream dimensions/FPS/count/audio with ffprobe afterward.

For article work, `svg TIME`/`frame TIME --svg` can export a frame. A returned SVG may rely on fonts/media not portable as-is; check a standalone rendered article fallback. Browser editor uses a WASM build and separate Node/wasm-pack setup, and was not tested here.
