# Motion timing starters for titles, labels and layout

Source: the principles in LottieFiles/motion-design-skill (MIT, https://github.com/LottieFiles/motion-design-skill), read on 18 Oct 2026 and restated in original words. That skill is written for interface animation. The rules below are starting points for text, labels and layout changes in an explainer. They were not validated on explainer videos here. Mathematical motion keeps the rule from references/visual-grammar.md: when a parameter is time, drive it linearly.

- Pick one easing family and one small set of durations (quick, standard, slow) for the whole video, and reuse them. Variety reads as noise.
- Things entering slow down as they arrive. Things leaving speed up as they go. Entrances can run somewhat longer than exits, because the viewer cares about what appears.
- Longer distance, longer duration. Do not give a label and a full-screen move the same time.
- Use the fewest properties that carry the change. One moving property is direct. Two is polished. More starts to compete with the idea.
- One hero element per beat. Everything else dims, as the persistent-diagram rule already says.
- Do not add decorative movement under an explanation. If it does not carry the idea, remove it.
- Write the numbers you chose into the timing file (stage 5 of references/staged-production.md) so a note like "a beat late" is a one-value change.

The source also gives specific millisecond ranges for interface elements. They are not copied here, because they are tuned for taps and page transitions, not for a viewer reading a label.
