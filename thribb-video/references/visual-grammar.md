# Visual grammar

Source: frame-sampled review of about 50 channel items (356 contact sheets, all viewed; no audio, no motion between samples, so timing and easing are not observed) plus the creator's stated advice. About 196 uploads were not reviewed. Style claims are patterns from the reviewed set.

## Principles

1. One color, one meaning. Pick a palette role table before drawing anything (for example: given quantity, unknown, result, caution). Never reuse a color for a second meaning in the same video.
2. Bind equations to the picture. Color each symbol the same as the object it stands for; when a change of variables happens, recolor the same equation so the binding survives. Use boxes, braces and labeled arrows rather than leaving the viewer to match by eye.
3. Reveal, do not display. Build formulas term by term; dim earlier terms; light the active one.
4. Persistent frame. Keep one diagram, table or number line on screen across a section and change it in place. Fill tables row by row, with the newest row emphasized and older rows dimmed.
5. Pinned roadmap. A list or tile strip with the current item lit and the others dimmed, brought back at each stage and at the end.
6. Smallest numbers first. Put concrete numbers on the figure before symbols. Show live readouts for anything that moves.
7. Visible failure. Mark a wrong guess with a clear tag, show it break, then show the repair.
8. Honest labels. When a drawing is a simplification, label it as one. When a model is a convenient lie, say so on the frame.
9. Surprise by data. Let a table or running count reveal a pattern before explaining it.
10. Real world as anchor. Footage or a prop belongs where the abstract thing needs to become tangible. Credit it.
11. Callout, not clutter. Arrows pointing at the exact step being discussed; question marks over what is unknown; a brace over the part that is a single number.
12. Same container, many cases. Small-multiple grids for initial conditions or parameter choices, so comparison is spatial.
13. Domain changes get a tint. When the argument moves to a different space, tint the whole frame and label the arrows between spaces.
14. Viewer-surrogate. Optional. If used, it voices the doubt as a thought bubble, never delivers the proof.
15. Recap tiles. Earlier results re-appear as small labeled thumbnails.

## Layout and legibility

- Text sits on a dark or backed-stroke field, readable at phone width.
- Keep the active area centered; keep the persistent frame in a stable corner or lower band.
- Dense algebra appears once, with margin annotations per step, then is replaced by a lighter restatement.
- Stillness is allowed when the viewer needs it to think (a pause on a question, a held result). Never add fake motion or a cosmetic changing readout to fill time; if a frame holds for several seconds, make sure the reason is visible (a question on screen, a result to read).

## Motion (unverified from stills, so partly from workflow notes)

From the Manim demo with a guest co-host (https://www.youtube.com/watch?v=rbu7Zu5X1zI; guest-co-presented, so treat as tooling practice, not core style; transcript-derived, original wording): drive a linear rate when time itself is the quantity; tie color to meaning; use updaters to follow tracked points; keep parameters explicit; orbit the camera slowly in 3D to give depth; split TeX into parts so highlights bind to meaning; use matching-string transforms for algebra moves; pin text in frame for 3D; back-stroke text for legibility; use a fast low-quality loop and a pre-run before a high-resolution render.

## Acceptance test for any frame

Cover the narration. Can a stranger tell what is the given, what is changing, what is being asked? If not, redraw.
